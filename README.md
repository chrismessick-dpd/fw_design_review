# Signoff FW — firmware design review

**Status:** prototype (2026-11-02).

**Live:** https://chrismessick-dpd.github.io/fw_design_review/

Signoff FW is Dovetail's checklist tool for firmware design reviews. It covers requirements and
architecture, the hardware interface, startup, memory and faults, concurrency, power, communications,
security, bootloader and updates, code quality, testing, and release and production. Each review is
one **target**: a firmware image such as the main MCU application or a co-processor's
firmware. Several targets can belong to one client project. Reviewers mark checks
Pass / Issue / N/A, discuss them in comment threads, track issues to Fixed or Waived, and print a
review report. Reviews sync through private GitHub repositories.

It runs on the same engine as [Signoff EE](https://github.com/chrismessick-dpd/ee_design_review)
and Signoff ME. Day-to-day use, requirements, keyboard shortcuts, sync, People & access and
contractor zips all work as they do in those tools; Signoff ME's README covers them in full.

- **196 checks in 11 checklists:** Requirements & Architecture, Hardware Interface, Startup,
  Memory & Faults, RTOS, Interrupts & Concurrency, Power Management, Communications, Security,
  Bootloader & Updates, Code Quality, Testing & Verification, and Build, Release & Production.
- **Firmware profile:** tag a target by execution model (bare metal, RTOS, multiple processors),
  connectivity (wireless, cloud, field updates, USB), power (battery, low power), I/O (display,
  sensing, outputs, motor control, storage) and context (security sensitive, functional safety,
  medical, volume production). Checks that don't fit are set aside as N/A, and you can still
  bring any of them back.
- **Demo mode:** `index.html?demo` shows the Smart Thermostat's firmware (`fdemo3`), the same
  made-up product as the other tools' demos. Signoff PL's demo links its firmware Part here, and
  its OTA and ESD System requirements flow down to this demo's REQ-001 and REQ-002.
- **Audit:** [docs/audit.md](docs/audit.md) explains how the first checklists were chosen and
  lists the firmware-specific features and suite work still to do.

## Repositories

| Repository | Holds | Who's on it |
| --- | --- | --- |
| `fw_design_review` (tool) | The tool and the checklists | FTEs |
| `fw_design_review_data` (data) | Internal FW reviews (`projects/<id>.json`) and People (`users.json`) | FTEs |
| `review-fw-<project>` (one per shared project) | That one review | FTEs and that project's contractors |

Its storage namespace is `signoff-fw.v1.`. The token (`signoff.token`) and theme are shared with
every Signoff tool.

## Layout

| Path | Contents |
| --- | --- |
| `index.html`, `assets/` | The tool (no build step, no dependencies) |
| `assets/config.js` | Everything FW-specific: name, repos, storage namespace, profile tags, stages, default checklists, ID prefixes, demo data |
| `assets/model.js`, `github.js`, `workspace.js`, `app.js`, `demo.js`, `styles.css` | The shared engine, vendored from `ee_design_review` (don't edit here) |
| `assets/templates.js`, `assets/version.js` | Generated by `tools/build.py` |
| `templates/*.json` | The checklists. See [docs/templates.md](docs/templates.md) |
| `tools/sync_engine.py` | Copies the engine from `../ee_design_review`; `--check` fails if it differs |
| `tools/build.py`, `package.py`, `validate_templates.py` | Shared engine tools (vendored) |
| `tests/test.html` | Model and sync tests against a fake GitHub API (open it over http) |

## Changing the tool or the checklists

- **Checklists, `config.js`, `index.html`, tests, docs:** edit here.
- **The engine:** fix it in `ee_design_review`, then run `python tools/sync_engine.py` here.

Then run `python tools/build.py` and open `tests/test.html` over http. It should say PASS.
Never reuse or renumber a check ID: reviews store their state by ID.
